# Abyssal — Deep Sea Mission Control

A Vite dashboard for dive telemetry, species observations, and scientific context. SpacetimeDB is the shared source of truth for submarine state, missions, discoveries, observations, sensor readings, and alerts. Species distribution comparisons query the public Ocean Biodiversity Information System (OBIS) API.

The exploration deck includes an interactive procedural terrain preview, shared submarine markers, transactional mission assignment and progress, a shared discovery journal, and synchronized sensor alerts with team acknowledgments. Movement and sensor samples are simulations; this dashboard does not control a physical vehicle. The simulated NAUTILUS-01 ROV seeds six clearly labeled sample reports locally and submits them to SpacetimeDB when connected, then adds a demo report every 45 seconds.

## Run the app

Requirements: Node.js and the SpacetimeDB CLI.

```powershell
npm install
npm run spacetime:generate
spacetime login
npm run spacetime:publish
npm run dev
```

Publishing updates the existing Maincloud database `hackutd2026-5b053` with the shared-state schema. The command does not clear database data. If it reports a breaking schema change, stop and review the CLI prompt rather than adding a data-deletion flag.

The client uses `wss://maincloud.spacetimedb.com` and the hackathon database name above. To point the frontend at a different server, set `VITE_SPACETIMEDB_HOST` in a local Vite environment file.

## Demonstrate real-time collaboration

For an isolated local test, start SpacetimeDB and publish to the local server:

```powershell
spacetime start
spacetime publish hackutd2026-5b053 --module-path spacetimedb --server local --yes
$env:VITE_SPACETIMEDB_HOST = "ws://127.0.0.1:3000"
npm run dev -- --host 127.0.0.1
```

Open the app in two separate browser profiles (or a normal and private window) so each has a different identity. Both clients subscribe to the same public tables. Select a waypoint and choose **Move submarine here**; the marker, coordinates, depth, and battery update for subscribers. Create a mission and assign it from either client; the server rejects a conflicting assignment. Advance its progress to completion. Submit a discovery, or use **Inject simulated anomaly** to create shared sensor alerts, then acknowledge an alert and confirm it changes in both windows. No page refresh or polling is needed. The dashboard persists state in SpacetimeDB; it does not pretend a reducer return value is the updated state.

To use Maincloud instead, publish with `npm run spacetime:publish` and leave `VITE_SPACETIMEDB_HOST` unset. Do not publish a schema change if the CLI indicates it will delete data or break clients without first reviewing the prompt.

## Marine observations

- Record common and scientific names, ocean region, coordinates, measured length, depth, sources, and notes.
- Coordinates are rounded to half-degree increments in the public table before subscribers receive them (roughly 55 km of latitude). Avoid entering sensitive locations in notes or public links.
- The age estimate is optional and only calculated if a cited reference adult length and lifespan are entered. It assumes linear growth and is not a validated age measurement.
- Conservation labels are crew-entered, not independently verified. Supply a trusted source (for example, an IUCN Red List species page); missing citations are marked unverified.
- “Candidate undescribed species,” “uncertain identification,” and “possible range extension” are review flags only. They are not claims of discovery; expert taxonomic review is required.
- OBIS occurrence grids describe records submitted to OBIS. They are not population estimates and may reflect sampling bias. The client sends only the scientific name to OBIS when a user runs a comparison; it does not send mission coordinates.
- The discovery scanner uses transparent rules on the mission log and simulated readings. It is not a trained AI model, species identifier, or conservation assessment.
- Terrain, suggested map locations, ROV position, battery values, and environmental readings are illustrative simulations. The map is not navigational bathymetry and the mission planner does not control a vehicle.
- Reducers authorize submarine updates against `ctx.sender`; mission assignments and progress are validated transactionally. Sensor alert thresholds are demonstration values. All sensor values generated by this app are marked simulated in the database.
- The public observation, discovery, mission, submarine, reading, and alert tables are visible to database subscribers. Use synthetic data only. Real ROV authentication/allowlisting and real hardware integration are not implemented.
- The ecosystem graph describes co-recorded taxon and depth context alongside the current simulated dive snapshot; it does not infer causation or species interactions.
- Attachments can be public image/evidence URLs or a compressed JPEG (up to 85 KB) stored on the public observation row. Uploaded images and observation text are shared with all database subscribers; do not attach private or sensitive media.
- Simulated robot reports are synthetic, locally cached for the demo, and never presented as actual animal sightings. When connected, they are copied to the shared observation and discovery tables with idempotent report IDs. The in-app stream can be paused.
